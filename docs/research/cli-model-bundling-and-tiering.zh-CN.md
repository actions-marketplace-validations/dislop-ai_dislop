# CLI 随包内置传统模型与分级选装小模型：实测依据与落地架构

更新日期：2026-11-22 · 状态：已落地生产实现（关联 [`pocket-slop-v1.json`](../../models/pocket-slop-v1.json)、[`manifest.json`](../../models/manifest.json)、[`pocket-model.mjs`](../../src/pocket-model.mjs)、[`local-model.mjs`](../../src/local-model.mjs) 与复现脚本 [`train_pocket_models.py`](../../scripts/train_pocket_models.py)）

这份报告用实测数据回答三个工程问题：哪些传统模型与微型模型可以直接随 `dislop` 基础包一起分发，体积边界划在哪里最合理，以及百 MB 到 GB 级的本地小模型怎样做安装选装与安全防呆。

---

## 1. 核心实测结论与三条工程纠偏

### 1.1 体积与能力的真实物理边界

在本机（`darwin-arm64`）对现有 CLI 包体、模型权重压缩率与原生推理运行时做实测后，不同技术路线的体积跨越了五个数量级：

| 分发层级 | 代表模型形态 | 压缩后新增体积 | 运行时依赖体积 | 冷启动与单段耗时 | 适合承担的任务 | 分发策略 |
|---|---|---:|---:|---|---|---|
| **T0 内置规则层** | 7 套场景规则包（42 条规则）+ 53 条多维模式库 | `~180 KB` | `0 MB` | `< 2 ms` | 客观交付残留、明确句法套路、前端/PPT 结构问题 | **随 CLI 默认打包** |
| **T1 内置传统集成模型** | `pocket-slop-v1.json`（去词面化 INT8 N-gram 语言模型 + 24 维线性归因 + 45 棵浅层 GBDT + 5 场景分类器） | **`14.6 KB`**（原始 `49.0 KB`） | **`0 MB`**（纯 JS / 纯 Python） | **`0.30 ms`** | 抓出避开全部禁用词的 2–4 句隐蔽温吞水段落、给出连续概率与可解释归因、无后缀文本自动判别文体包 | **随 CLI 默认打包** |
| **T2 轻量神经编码器（实测评估）** | INT8 量化双语序列分类模型（`.onnx`） | `~28 MB` | **`122.5 MB`**（`onnxruntime` 原生包实测解压体积） | 冷加载 `~45 ms`，单段 `~12 ms` | 仅能分类打分、无法改写文本，且空运行时就超 `100 MB` | **不进默认包**（分类已由 `14.6 KB` 内置集成覆盖） |
| **T3 选装本地生成小模型** | `Qwen3` 双语指令模型（`0.6B` / `1.7B` / `4B` Q4_K_M） | **`520 MB` / `1.3 GB` / `2.5 GB`** | 复用本机 `ollama` 或 `llama-server`（`127.0.0.1`） | 单段生成 `0.4 s – 3.5 s` | 纯离线本地段落去味改写与审校（须套死外部事实锁） | **硬件感知按需选装**（`dislop setup` / `dislop model install`） |

核心判断非常明确：**传统统计与树集成模型完全应该随 CLI 默认打包**——加上它之后，整个 `npm` 发布包仍控制在 `300 KB` 量级，且 Node、Python、本地 MCP、浏览器工作台以及未来的轻量 VS Code Web 扩展可以共用同一份 JSON 权重。反过来，**任何依赖 `onnxruntime`、`llama-cpp-python` 或百 MB 权重的神经网络模型都绝不能塞进默认依赖**，否则单一个 `122.5 MB` 的运行时就会击穿 PyPI 默认 `100 MB` 单包限制，拖慢每一次 `npx dislop check`，并在缺少编译环境的内网办公机上引发安装失败。

### 1.2 三条必须提前避开的误区

1. **误区一：以为塞一个几十 KB 的微型神经网络会比传统模型更准**。在百至千级精标样本规模下，对照实验直接推翻了这个直觉：用 PyTorch 训练并量化为 INT8 的哈希嵌入双层神经网络（`17.2 KB` gz）在本仓 86 个真实文档段落上的误报率高达 **`15.1%`**，在隐蔽温吞水测试集的干净样本上误报达 **`33.3%`**。相比之下，先把主题实词脱敏为词法骨架再做 INT8 对数似然比 + 线性归因 + 浅层梯度提升树的传统混合模型（`14.6 KB` gz），在全部盲测集与本仓真实文档上实现了 **`0.0%` 误报**，还能精确列出前三大触发原因。
2. **误区二：在 `npm install` 或 `pip install` 的安装钩子里弹交互框让用户选装大模型**。现代包管理器（`npm` v7+、`pnpm` v10、`uv`、`pip`）默认静默或直接拦截 `postinstall` 脚本，没有交互式终端输入；一旦在安装钩子里尝试交互或拉取数百 MB 权重，CI 流水线、Docker 构建和企业代理会立刻超时挂死。稳妥的工程做法是：**安装命令本身保持毫秒级纯离线代码落盘，装完后由显式的 `dislop setup`（交互式终端菜单）或 `dislop model install --tier <档位>` 负责硬件探测与选装，同时支持内网环境用 `dislop model import <权重文件>` 做离线 SHA-256 校验导入**。
3. **误区三：让选装的本地 `0.6B–4B` 小模型直接通篇改写文稿**。小参数生成模型最常见的翻车点有两个：一是顺手漏掉数字或把边界限定词删掉（例如把 `故障恢复最多 45 秒` 改成 `故障恢复 45 秒`），二是把一阶套话改成 `不是 A，而是 B` 式的二阶口号。因此本地小模型改写（`dislop deslop --local`）必须采用**问题段落局部送审 + 内部数字与边界限定词保真护栏 + 二次规则校验**：干净段落根本不进模型；改坏数字或限定词时自动带错误原因重试一次，仍不过关就退回原段并标明原因。

## 2. 内置传统模型的去词面化设计与六范式盲测对比

### 2.1 为什么规则抓不到「隐蔽温吞水段落」

现有 53 条规则与模式库（42 条规则包 + 11 条扩展模式库）在包含禁用词、分号排比、破折号堆叠、自问自答或 5 句以上等长句的样本上能做到极高检出，但当大模型写出只有 2–4 句、避开所有黑名单词汇的平庸公关段落时（见盲测集 [stealth-vapor-v1.json](../../benchmarks/datasets/stealth-vapor-v1.json)），单点规则与 5 句变异系数门禁全部保持静默，召回率为 **`0.0%`（`0/12`）**。

这类段落的真实统计特征集中在三处：
- **去词面化结构转移高度可预测**：把具体业务名词掩码为 `<WC>` / `<H>`、保留虚词与抽象词缀（英文 `-tion/-ment/-ity/-ness` 与分词起句，中文 `在……的过程中`、`……的推进`、`往往能够`、密集 `的` 字链）后，相邻结构二元/三元组的转移概率几乎全落在训练分布峰值上。
- **分句节奏匀称但缺乏具体锚点**：即使只有两三句话，内部逗号分句的长度依然高度整齐，且缺少数字、时间、文件路径、内联代码或文献引用。
- **不能靠「有没有阿拉伯数字」偷懒判别**：人类写的定性经验总结或叙事散文同样可能不含阿拉伯数字。因此训练与盲测集中专门加入了不含数字的朴实人类段落（带有明确动作动词、第一/二人称主语或具体日常物象），强迫模型区分「空洞名词化缓冲腔」与「无数字的朴实人话」。

### 2.2 六种可打包模型范式的零泄漏盲测结果

训练池严格隔离（共 `470` 条文本样本，包含各规则包 `bad/trap/good` 同题三态对照与既有训练集，按归一化哈希剔除一切测试集文本），在三组完全未参与训练的盲测集上对比：
1. `holdout-v1` + `holdout-v2`（`36` 条跨领域未见样本）；
2. `stealth-vapor-v1`（`24` 条同题配对的 2–4 句中英文隐蔽温吞水正负样本，现有规则召回率 `0.0%`）；
3. 本仓真实文档段落压测（`15` 份正式 Markdown 文档切出的 `86` 个正文段落，以及 `site/` 下全部页面文档，要求 `0` 误报）。

| 方案 | 原始体积 | Gzip 体积 | `stealth-vapor-v1` F1（召回 / 干净误报） | `holdout-v1+v2` 干净误报 | 本仓 86 个真实段落误报 | 结论 |
|---|---:|---:|---|---|---:|---|
| **M0 仅现有规则与模式库** | — | — | `0.0%`（召回 `0.0%` / 误报 `0.0%`） | `0.0%` | `0 / 86` | 避开显式词表与 5 句门槛后漏检 |
| **M1 传统字符 TF-IDF（3000 维 LR）** | `94.7 KB` | `29.4 KB` | `87.0%`（召回 `83.3%` / 误报 `8.3%`） | `17.6%` | `0 / 86` | 记住局部话题词，跨领域干净样本误报偏高 |
| **M2 去词面化 INT8 N-gram 语言模型** | `25.0 KB` | `5.3 KB` | `91.7%`（召回 `91.7%` / 误报 `8.3%`） | `23.5%` | `9 / 86` | 序列可预测性信号强，但单独做门禁会误伤说明文 |
| **M3 去词面化 24 维统计 + LM 线性模型** | `25.7 KB` | `5.7 KB` | `92.3%`（召回 `100.0%` / 误报 `16.7%`） | `17.6%` | `8 / 86` | 归因清晰，缺非线性具体度阻尼 |
| **M5 微型 INT8 神经网络（PyTorch MLP）** | `23.2 KB` | `17.2 KB` | `72.0%`（召回 `75.0%` / 误报 `33.3%`） | `23.5%` | `13 / 86` | 百级样本下哈希嵌入过拟合，误报最高 |
| **M6 生产版内置混合集成（`pocket-slop-v1`）** | **`49.0 KB`** | **`14.6 KB`** | **`100.0%`（召回 `100.0%` / 误报 `0.0%`）** | **`0.0%`** | **`0 / 86`** | 兼顾序列转移、线性归因与 45 棵浅层树非线性护栏，Node/Python 逐项一致 |

## 3. 已落地的分级打包与选装架构

### 3.1 默认随包层（`models/pocket-slop-v1.json`，`14.6 KB` gz）

无需任何额外安装，所有 `npm`、`PyPI` 与源码用户默认拥有两项内置传统模型能力：
1. **段落级隐蔽水文评分与特征归因（`pocket-slop-ensemble`）**：通过 `dislop model score <文件>`、`dislop check --ml` 或 `dislop check --profile` 调用，自动屏蔽代码块、Markdown 表格、`dislop-quote` 引用区与括号内反面案例引文，并把文献引用（如 `(Vaswani et al., 2017)`）和相对路径链接计入具体锚点。
2. **无后缀文本场景自动路由（`pocket-pack-router`）**：通过 `dislop check - --pack auto` 对标准输入或无后缀草稿自动判别最匹配的规则包（`business-brief`、`engineering-spec`、`regulated-comms`、`literary-essay`、`deck-and-ui`）。

### 3.2 按需选装层（`models/manifest.json` + 硬件护栏 + 离线导入）

针对需要本地离线改写的用户，按硬件内存与磁盘空间提供显式选装：

- **交互式引导与一键选装**：运行 `dislop setup`（终端交互选单）或 `dislop model install --tier auto|none|fast|balanced|quality`（支持 `--dry-run` 预览执行计划）。当用户机器内存低于安全线（例如在 `4 GB` 内存环境强装 `quality` 档 `4B` 模型）时，自动拦截并给出推荐档位提示，传 `--force` 才允许强制继续。
- **内网离线导入与完整性核验**：支持 `dislop model import ./Qwen3-1.7B-Q4_K_M.gguf --tier balanced --sha256 <摘要>`，流式计算 SHA-256 并原子写入 `~/.cache/dislop/models/`（可通过 `DISLOP_MODEL_DIR` 自定义目录），同时提供 `dislop model remove` 清理缓存。
- **本地回环自愈改写（`dislop model deslop` / `dislop deslop --local`）**：默认严格限制只向本机回环地址（`127.0.0.1` / `localhost` / `::1`）发送请求，拒绝外网地址以防误传草稿；仅抽取出问题段落交由本地小模型压缩，并对每段改写结果强制执行内部数字与边界限定词保真护栏，任何丢数字或删限定词的改写若重试仍失败则自动回退原段。
