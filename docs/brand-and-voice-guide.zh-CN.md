# 品牌风格、表达规范与设计基准

[English](./brand-and-voice-guide.md)

> 一句话总纲：**底盘如机印般沉稳，落笔如手批般轻快。**
>
> `dislop` 用机器守住网格、坐标、对比度与事实核对；用带人味的一笔，把废话圈出来，把好句子留给作者。

---

## 1. 为什么去 AI 味必须建立自己的品牌人格

删掉套话只是下限。一个专门帮人去 AI 味的工具，如果自己说话像一份冷冰冰的合规审阅终端，读者会觉得它靠谱，但很难记住它，更看不到“有活人感的表达”究竟长什么样。

反过来，如果靠表情符号、感叹号或俏皮话堆人设，又会伤及“零误报、不篡改数字、CI 可托付”的工程底气。

答案其实已经画在我们的图标 [assets/logo.svg](../assets/logo.svg) 里了。

### 从图标几何里读出品牌性格

| 图标里的细节（`assets/logo.svg`） | 对应的品牌性格与设计许可 |
|---|---|
| 圆角深碳黑底座（`#14171A`，`12/64` 圆角） | **沉稳的工程底盘**：数字、行号、退出码与 `[SKIP]` 覆盖边界平铺直叙，绝不油滑。 |
| 朱红笔画底下仍留着浅灰原稿线 | **尊重作者原文**：先指明原稿的片段，不抹掉作者声音，绝不替人偷偷改稿。 |
| 笔画顺着原稿走过一半才向上绕出**一个**大圆环 | **每屏最多一处俏皮**：克制而灵动，只在中性状态或通过状态轻轻眨一下眼。 |
| 圆润笔端（`stroke-linecap="round"`，`6/64` 粗细） | **温柔但不含糊**：下手利落却不扎人；只谈文字或版式片段，从不训斥作者。 |
| 笔尾轻快向右下挑出，原稿其余部分原样不动 | **收笔干脆**：给出下一步动作后立刻放手，剩下的空间留给作者自己决定。 |

### 品牌原型：坐在你身旁的责任编辑（Desk / Copy Editor）

比机械校对员更往前走半步——`dislop` 是一位肯在页边写清缘由、也知道什么时候该收笔的**责任编辑**：

- 遇到换谁来看都是错的硬伤（漏出的本机路径、空链接、没填的占位符），**红笔**直接划掉，给明确改法；
- 遇到因文体而异的套话与节奏，**蓝笔**只在页边问你一句，去留由你说了算；
- 遇到原稿里立得住的数字、限定词、链接与代码，**绿点（保留号 `stet`）**稳稳托住，改稿后与原稿对一遍；
- 从不把所有作者改成一个腔调，而是帮你保留自己的声音。

### 四组张力边界（怎么拿捏“俏皮、温柔、沉稳”）

| 张力维度 | 成立的做法 | 越界的禁区 |
|---|---|---|
| **俏皮，但不幼稚** | 用编辑台本身的动作和一句冷幽默点题；同一界面、单次 CLI 输出或更新日志最多留一处轻巧收尾，且只出现在中性说明或通过态 | 表情符号、感叹号、`!`、吉祥物脸谱、玩梗段子、嘲讽 AI 或作者、在报错/拦截里抖机灵 |
| **温柔，但不含糊** | 放软对人的姿态：批注只描述文本片段，文体商榷用问句，允许作者带理由豁免 | 放软客观事实：在 `error` 上写“也许/可能/看起来像”，或者用“太棒了”这类空洞夸奖 |
| **沉稳，但不端着** | 每句主张紧扣一个真实数字、位置或命令，边界开诚布公 | 首屏同一组统计反复念三遍，或者把 `多态`、`多集`、`底层架构` 这类规格词直接印在按钮上 |
| **有主张，但不说教** | 给出 `反例 → 二阶陷阱 → 示例改稿` 对照，偶尔展示同一句的两种合规改法 | 居高临下批判“垃圾内容”，或在文末加一段升华口号 |

> **俏皮话同样要过删除测试**：把那点小俏皮删掉，这句话依然得留下一条实打实的事实。例如工作台隐私说明：`稿子只留在这个标签页里。页面的 CSP 把 connect-src 设成了 'none'，想往外发也发不出去。`

## 2. 表达风格规范（中英文母语对等）

核心总规则：**两支笔，两种语气**。红笔（`error`）陈述事实与改法；蓝笔（`warning` / `info`）向作者发问；绿点（`stet`）如实回显保留下来的原词。

中英文各自按母语习惯重写，绝不做字对字翻译腔。例如英文清样通过写 `Pass for press.`，中文对应写 `可以付印。`——各用各的行业活话。

### 五大触点对照（旧稿 → 品牌基准）

| 触点 | 英文（旧 → 建议） | 中文（旧 → 建议） |
|---|---|---|
| **官网首屏** | 37 词塞满 H1 → **H1**：`De-slop AI outputs.`<br>**副句**：`Paste a draft, a deck, or a page. dislop strikes what can't ship, asks about what sounds canned, and checks that your edit kept numbers, links, and citations.` | 堆叠扩展名长句 → **H1**：`全面去 AI 味。`<br>**副句**：`把稿子、PPT 或页面贴进来。不能发的硬伤，dislop 直接划掉；听着像套话的地方，它问你一句；改完再替你和原稿对一遍，数字、链接和引用一个不少。` |
| **工作台控件与隐私** | `Load Clean Revision` → `Show a clean edit`<br>`Try 2nd-Order Trap` → `Try an overcorrection`<br>`100% in browser memory...` → `Your draft stays in this tab. The page's CSP sets connect-src 'none', so it couldn't phone home if it tried.` | `载入合规改写稿` → `看一版改好的`<br>`测试二阶套话陷阱` → `试一版改过头的`<br>`物理锁死外发请求` → `稿子只留在这个标签页里。页面的 CSP 把 connect-src 设成了 'none'，想往外发也发不出去。` |
| **工作台状态与眉批** | `✓ Clean proof sheet (0 findings).` → `Pass for press. 0 findings; protected spans stayed as written.`<br>空稿：`Nothing on the sheet yet. Paste a draft, or pick a specimen on the left.` | `✓ 清样无命中（0 findings）。` → `可以付印。0 处标记，原稿里的受保护事实完好保留。`<br>空稿：`校样单还是空的。贴一段稿子进来，或者从左边挑一份标本。` |
| **README 与文档** | 首段连塞四串长列举 → `dislop checks the things models write for you... It never rewrites your text. The edit is yours.`<br>标题：`Why Two Tiers Exist` → `Red pencil, blue pencil` | 术语开场 → `dislop 是给模型代笔的东西做体检的工具……它不替你改稿。笔在你手里，它只管看。`<br>标题：`为什么要做两层分治` → `红笔和蓝笔` |
| **版本发布与对外分享** | 仅列文件路径清单 → 三拍写法：① 这一版能多查什么；② 一行怎么用；③ 还有什么读不了（诚实边界永不省略）。例如：`dislop 0.2.0 发了。这版多了 dislop verify：改稿时丢了哪个数字、哪条链接、哪处引用，它会逐条列出来。` | 同左，中文口语利落收尾，附 `dislop.com` 入口。 |

### 诚实措辞红线

- **不用“verify every fact / 核验所有事实”**：`dislop verify` 确定性核对的是数字、限定词、单位、日期、URL、代码片段与引用标记是否原样保留，不替人判断外部世界真伪。对外统一表述为 **「改完和原稿对一遍（Check your edit against the original）」**，并在说明中写清核对的七类锚点。
- **区分“未检查”与“无问题”**：空稿、加密 PDF、跳过压缩流各有独立提示，绝不混进“通过”。
- **减少高频口癖词**：同一页面避免反复用 `zero` / `零` 当强调副词；中文界面不夹带未翻译的 `0 findings`，不用 `硬核`、`物理锁死`、`合规改写稿` 等报告腔词；英文用自然单复数，不用 `finding(s)`。

## 3. 视觉、平面与 UI 风格基准

完整色值与 WCAG 2.2 实测表维护于 [design-system.zh-CN.md](./design-system.zh-CN.md)，本节确立把图标气质延伸到全站的**双层视觉语法**：

### 3.1 双层架构：机印校样底盘 + 手批圆头笔迹

1. **底层（机印校样底盘）**：保持 `1px` 连续建筑标尺、直角共享单元格（`0px`）、冷中性棉浆纸（`#F6F7F5` / `#FFFFFF`）与深色单调明度阶梯（`#0E1012 → #15181C → #1D2127`），零外部字体 CDN，零外发请求（`CSP: connect-src 'none'`）。不碰蓝紫霓虹渐变，也不碰暖米白陶土模板（护栏：任何表面色不落入色相 `20°–70°` 且饱和度 `> 8%` 的区间）。
2. **表层（手批圆头笔迹）**：把图标的圆头笔触与轻盈弧线引入真实批注与交互控件，**但每一处手批记号都必须绑定真实命中或事实，绝不做纯装饰花纹**。

### 3.2 一支朱红，三种笔压（Ink Pressure）

`assets/logo.svg` 的主朱红（`#F04438`）与正文的红笔错误色同属色相 `4°–6°`，按笔触粗细与主题分工：

- **笔迹朱红 `--pen`（`#F04438`）**：专用于 `>= 2.5px` 的粗笔划与图标主圆环，**浅色与深色模式保持同一枚朱红**（深色横幅与页面图标不再把 logo 改成浅橙粉）；绝不用于浅色小号正文。
- **浅色正文红 `--mark-error`（`#B42318`，白底 `6.6:1`）**：浅色模式文字与细下划线。
- **深色正文红 `--mark-error`（`#FF7A6B`，深纸 `7.0:1`）**：深色模式文字与细下划线。
- **深色底座可见性**：深色模式下图标外框加 `1px` 细边界（`--rule-strong`），避免 `#14171A` 底座融进 `#15181C` 顶栏。

### 3.3 三种批注记号（去色盲依赖的独立几何）

| 记号 | 语义 | 线型与视觉 | 色彩令牌 |
|---|---|---|---|
| **删除号（`dele`）** | 客观硬伤（`core` `error`） | `2px` 实线下划线（平面海报/横幅用圆头删除环） | `--mark-error` / `--pen` |
| **商榷线（`query`）** | 文体提示（`warning` / `info`） | `1.5px` 虚线下划线（`dashed`） | `--mark-warn` |
| **保留点（`stet`）** | 受保护事实（数字/限定词/链接等） | `2px` **圆点下划线（`dotted`）**，与蓝虚线彻底拉开几何区分 | `--mark-stet` |

### 3.4 形状、字体与动效纪律

- **形状三层**：贴合标尺的单元格与表格保持 `0px` 直角；可按按钮采用与图标同比例的柔和圆角（`--radius-ctrl: 6px`，小按钮 `5px`）；内凹输入框与代码槽用 `--radius-input: 4px`；禁止 `999px` 胶囊标签堆砌。
- **字体角色**：等宽字体（`--font-mono`）只用于代码、行号、坐标、规则 ID 与计数；正文说明、按钮、隐私提示、图例与页脚说明优先回到系统无衬线与衬线，洗掉“命令行终端”式的冷硬感。中文标题在 `html[lang^="zh"]` 下设 `letter-spacing: 0`（取消负字距，避免汉字拥挤）。
- **动效节制**：常规交互过渡 `<= 120ms`；仅在用户明确触发“删除/校验通过”这类笔迹动作时允许一次克制的 `240–300ms` `ease-out` 笔锋过渡，且严格遵循 `prefers-reduced-motion: reduce`。

## 4. 贡献者与 Agent 自检清单（8 项是非题）

撰写或审校 `dislop` 自身的任何对外文档、官网文案、发布公告或平面图前，逐条自核：

1. 首句是否落在了具体对象上（一段原文、一个文件、一个数字或一条命令）？
2. 数字、级别名称与退出码是否平实准确、原样引用，且首屏每句最多出现一个证明数字？
3. 客观硬伤是否给了直接改法，文体提示是否把决定权留给了作者？
4. 同一页面是否最多只有一处轻巧/俏皮表达，且绝不出现在报错或拒绝提示里？
5. 把那句俏皮表达删掉后，原句是否依然保留了一条完整事实？
6. 中英文是否各自按母语意思独立写成，中文界面里未夹带可翻译的英文统计词？
7. 视觉上是否守住了直角标尺、圆头笔迹只绑真实标注、朱红仅用于 `dele`、绿点用于 `stet`？
8. 公开文案是否通过 `dislop check <file> --fail-on info`（Node 与 Python 双端 0 命中），且无 `!`、表情符号与 `(s)` 机械复数？

配套机读声纹参考文件维护在 [docs/brand/voice.json](./brand/voice.json)（遵循 `dislop.voice/1` 草案协议）。
